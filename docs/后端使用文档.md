# ClassSoftwareHub 后端使用文档

> 面向接入方与维护者。本文描述运行在 EdgeOne Pages 上的后端服务（下称「新后端」）的架构、端点契约、配置方式与运维操作。
> 旧 Cloudflare Worker 后端（cshapi / submit.132614.xyz）的迁移已基本完成，两者的差异见 §2.3。

---

## 1. 服务概况

| 项 | 值 |
|---|---|
| 线上地址 | `https://api.classsoftwarehub.cn`（根路径即状态页） |
| 运行平台 | 腾讯云 EdgeOne Pages Functions（V8 运行时） |
| 代码仓库 | `github.com/c1201y/csh-api`，分支 `main` |
| 入口文件 | `functions/api/[[default]].js`（API），`functions/status.js`（状态页），`functions/index.js`（根路由转发） |
| 部署方式 | GitHub Git 集成，push `main` 自动构建部署 |
| 状态存储 | EdgeOne Blob（`@edgeone/pages-blob`，命名空间 `csh-state`，强一致读） |
| 对象存储 | 阿里云 OSS，桶 `classsoftwarehub`（华东2 / cn-shanghai，V4 签名） |
| 下载中继 | ECS 中继（`http://8.159.148.101:8091`，经 OSS **内网**端点取流） |

## 2. 架构

### 2.1 组件关系

```
浏览器 / 桌面端
   │  HTTPS
   ▼
api.classsoftwarehub.cn（EdgeOne Pages Functions）
   ├── /api/status ……………… 状态页与自检（无鉴权）
   ├── 提交类（submit / echocave / feedback）→ GitHub API（建审核 PR / Issue）
   ├── /api/oss-sign ………… OSS V4 预签名（PUT），客户端直传 OSS
   ├── /api/license/activate … 激活码换授权令牌；提交类路由前置正版校验（见 §8）
   ├── /api/mirror-sign …… 代签 GitHub 加速节点限时直链（服务端持有节点密钥）
   ├── 下载类（dl-ticket / dl / icon）→ 双通道取流，见 §4.3
   │      ├── 方法一：ECS 中继（内网取流，不计 OSS 公网流量）
   │      └── 方法二：后端直连 OSS 签名 URL
   ├── 管理类（purge / files / gc / dl-mode …）→ X-Purge-Token 鉴权
   └── 状态数据（登记表 / 票据 / 用量 / 喊话）→ EdgeOne Blob
```

### 2.2 状态存储模型

Blob 命名空间 `csh-state`，主要键：

| 键 | 内容 |
|---|---|
| `gate:files` | 文件登记表（key、来源前缀、大小、synced/claimed 状态） |
| `gate:cfg` | 运行配置（下载模式、GC 时间戳、孤儿阈值等） |
| `gate:stats` | 月度用量统计（relay / direct 字节数） |
| `gate:device:*` | 设备维度下载计数（按天） |
| `gate:tickets` / 票据记录 | 下载票据与设备指纹绑定 |

代码内通过 `makeGate` 在函数内复刻 Durable Object 的 `idFromName`/`get` 语义，上层调用方式与旧版一致。

### 2.3 与旧 CF Worker 后端的差异

| 维度 | 旧后端（CF Worker） | 新后端（EdgeOne Pages） |
|---|---|---|
| 下载取流 | `cloudflare:sockets` 原生 TCP 连 ECS 中继 | 中继为普通 HTTP 服务，`fetch()` 直连（行为等价） |
| 状态存储 | CF KV + Durable Object | EdgeOne Blob |
| 状态页 | 无 | `/api/status` + 根路径直达 |
| 垃圾回收 | `scheduled` cron 定时 | 无 cron，`dl-ticket` 请求触发懒加载 GC（20 分钟节流） |
| 配置 | 全部走 wrangler secrets | 非敏感值内建 `ENV_DEFAULTS`，敏感值走环境变量 |
| 域名 | cshapi / submit.132614.xyz | api.classsoftwarehub.cn |

**业务代码零改动**：迁移时对提交链路（submit / echocave / feedback / oss-sign / dl-ticket 等）做了逐函数比对，签名算法、字段白名单、限流策略与旧版一致；实质改动仅集中在下载取流与状态存储两层。

## 4. 核心链路

### 4.1 软件投稿 `/api/submit`

1. 客户端 POST 投稿 JSON（含 `_类型` 等白名单字段，`_` 前缀字段携带元信息）；
2. 服务端做字段清洗、年龄校验（`age` 密文）、来源校验、频次限制（默认 6 次/天、待审 3 条）；
3. 通过 GitHub API 在 `submissions/` 目录创建审核草稿，由仓库的 `review-submission.yml` 工作流驱动人工审核；
4. 审核通过后工作流将数据并入 `软件数据/apps/`，并调用 `/api/purge` 清理被拒绝稿件的桶对象。

服务端仅做「创建草稿」，不直接改数据目录——所有上线动作都经过审核流。

与「系统」相关的投稿字段（新版投稿页为多选，见站点 `软件数据/platforms.json`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `system` | string | 展示文本（如 `Windows 10+ / macOS 12+`），由投稿页按平台 + 版本拼出 |
| `platforms` | string[] | 平台 key 数组，**原样进入站点数据**，首页「系统」筛选用；缺省视为旧版投稿，由审核流按 `system` 文案兜底推导 |
| `_系统版本` | object | 审核用元数据：平台 key → 版本 key 数组，仅出现在审核 Issue；合并进站点数据前被 `review-submission.yml` 剥掉 |

校验规则：

- `platforms` 元素须匹配 `/^[a-z0-9][a-z0-9.-]{0,30}$/`，最多 16 个，服务端归一化（小写、去重）；
- 能读到站点 `软件数据/platforms.json` 时，额外核对 key 必须是已定义平台（读不到则跳过核对，不阻断投稿）；
- `_系统版本` 只保留已选平台下的合法版本 key（每平台最多 32 个）。

其他与新版投稿页对齐的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `category` | string | 必须是站点 `软件数据/categories.json` 定义的 key（当前为 `classroom` / `office` / `system` / `media` / `network` / `utility`，服务端常量须与该文件保持同步）；旧分类 key（`schedule` / `teaching` / `other`）已随站点数据迁移废弃，投稿会被拒 |
| `downloads[].kind` | string | 下载方式，白名单 `file` / `store` / `netdisk` / `page`（与站点 `downloadLink.ts` 的 `DECLARED` 一致）；合法值**原样进入站点数据**，非法值丢弃后由详情页按链接自动推断 |

### 4.2 OSS 直传 `/api/oss-sign`

请求：`{ "name": "文件.exe", "size": 123456, "contentType": "application/octet-stream", "purpose": "upload" | "icon" }`

响应：`{ url, key, contentType, expiresIn }`

要点：

- **签名锁 Content-Type**：PUT 请求必须原样携带响应里的 `contentType`，否则 OSS 返回 `SignatureDoesNotMatch`（curl 不显式带头会默认塞 `x-www-form-urlencoded`，是最常见故障）；
- 大小上限：普通上传 2.5 GiB，图标更小（见代码常量）；
- key 规则：`upload/YYYY/MM/<uniq>-<safe-name>`，图标为 `icon/YYYY/MM/...`；
- 限流：按来源 IP 哈希，超限返 429 并带 `scope`。

### 4.3 下载（双方法）

`/api/dl-ticket` 请求：`{ "key": "releases/2026/10/xxx.zip", "fp": "<设备指纹>" }`

响应：`{ success, mode, url, key, expiresIn, dailyLimit, remaining }`

`mode` 即服务端选定的通道：

| mode | 取流路径 | 费用 |
|---|---|---|
| `relay` | 后端 → ECS 中继 → OSS 内网 | 不计 OSS 公网流量 |
| `backend` | 后端 → OSS 签名 URL → 客户端 | 计 OSS 公网下行 |
| `direct` | 客户端 → OSS 签名 URL | 计 OSS 公网下行 |

- **auto（默认）选路链**：中继（配额内）→ 直探测活 → 失败转 `backend` → 再不行 `direct`。探活为独立请求，不走内部回落，避免每个下载请求都先撞一次不可用的中继；
- 票据 15 分钟有效，签名绑定 `key + 设备指纹 + mode`；`/api/dl` 按票据里的 `m` 参数决定上游，旧格式票据（无 `m`）天然兼容；
- 每设备每天默认 25 次（`DL_DAILY_LIMIT`）；
- `/api/dl` 透传上游原生流（含 `Range` / 206 / `Content-Range`），支持断点续传。

### 4.4 教室喊话

`/api/announce/send` 以 6 位配对码鉴权（与桌面端配对流程一致），写入 Blob；教室机桌面端通过 `/api/announce/poll?deviceId=...&pairCode=...` 轮询。发送可限定 `targets`（设备 ID 十六进制串）。

### 4.5 管理端点

所有管理端点统一使用请求头 `X-Purge-Token: <PURGE_TOKEN>`。典型用途：

- `/api/purge`：审核流删除被拒绝稿件的对象（`requireRegistry: true` 时先查登记表，键不在表里拒删，防误删他人文件）；
- `/api/gc`：清理孤儿对象（登记表外且超过阈值的对象）与过期登记，默认 dry-run，传 `{ "dry": false }` 执行；
- `/api/registry-sync`：桶实况与登记表对账，默认 dry-run；
- `/api/promote`：审核通过后把 `upload/` 对象迁移到 `releases/`（引用保持不变）。

### 4.6 管理后台（`/admin`）

维护者工具，页面 `functions/admin.js`，数据走 `/api/admin/*`。**不是公开能力**：未配置
`CSH_ADMIN_PASS` 时登录接口直接回 503「后台未配置」。

| 能力 | 说明 |
|---|---|
| 登录 | 账号密码来自环境变量；会话 12 小时，Cookie `csh_adm`（`HttpOnly; Secure; SameSite=Strict`），HMAC 签名，服务端无状态 |
| 签发激活码 | 一次 1–50 个，可填备注；序列号取 `lic:seq` 与索引最大值加一；结果可单个或全部复制 |
| 签发记录 | 最近 200 条：码、备注、签发时间、状态（未使用 / 已激活 / 已吊销 / 外部签发） |
| 设备列表 | 最近 200 台：设备码、首次与最近活跃时间、码尾号、构建号、封禁状态。凡带设备码的客户端请求都会登记（6 小时节流），未激活的设备码尾号为空 |
| 封禁 / 解封 | 时长 1 天 / 3 天 / 7 天 / 30 天 / 永久，原因会原样展示给用户 |
| 吊销 | 仅对**未激活**的码有效；已激活的码接口返回 409，只能封禁设备 |
| 在线喊话 | 列出有心跳的在线客户端（教室喊话轮询 3 分钟内），可定向或全量推送一条喊话，时长 10–120 秒、落款默认「管理员」；后台触发不受 10 秒/配对码限频 |

防护：同源校验（`Sec-Fetch-Site` + `Origin`/`Referer`）、错误密码同 IP 30 分钟内 10 次锁定、
密码定长比较、响应 `no-store` 且不带 CORS 头。因为 Cookie 带 `Secure`，后台须经 https 访问。

在线喊话复用教室喊话通道：在线列表扫 `gate:ann:d:<配对码>` 注册表，投递按配对码分组调用
`ann-send`（`targets` 只含选中设备）。因此**只有开启了教室喊话轮询的客户端才可喊话**，
仅发过普通请求的设备会出现在设备列表里，但不在在线列表。

副作用需知情：`licenseGuard` 现在会为每个受保护请求读一次 `lic:ban:<device>`（一次 KV 读）；
激活成功额外写两个索引（各一次读 + 一次写），用于后台展示。

## 5. 环境变量

在 EdgeOne Pages 项目设置中配置（Git 集成构建时注入）。**敏感变量只放这里，不要写进仓库**（仓库为公开历史，曾发生凭据泄露，见 §9.1）。

| 变量 | 必填 | 说明 |
|---|---|---|
| `OSS_ACCESS_KEY_ID` | 是 | OSS AK（RAM 子号即可） |
| `OSS_ACCESS_KEY_SECRET` | 是 | OSS SK |
| `RELAY_HOST` | 是 | ECS 中继地址（当前 `8.159.148.101`） |
| `RELAY_PORT` | 否 | 中继端口，默认 `8091` |
| `RELAY_TOKEN` | 是 | 中继 `X-Api-Key` 校验值 |
| `SIGN_API_KEY` | 是 | GitHub 加速节点 `/sign` 的 X-Api-Key |
| `DL_SIGN_SECRET` | 是 | 下载票据 HMAC 密钥（仅服务端使用，轮换零影响） |
| `PURGE_TOKEN` | 是 | 管理端点令牌 |
| `GITHUB_TOKEN` | 是 | GitHub PAT（Contents 读写 + Issues），驱动投稿审核流 |
| `RELAY_SCHEME` | 否 | 中继协议，默认 `http` |
| `ALLOWED_ORIGIN` | 否 | CORS 白名单，逗号分隔；默认 `*` |
| `CSH_ADMIN_USER` | 否 | 后台账号，默认 `admin` |
| `CSH_ADMIN_PASS` | 是* | 后台密码；与 `CSH_ADMIN_PASS_SHA256` 二选一（*后台要用就得配） |
| `CSH_ADMIN_PASS_SHA256` | 否 | 密码的 SHA-256 十六进制，优先于明文密码 |
| `CSH_ADMIN_SESSION_SECRET` | 否 | 会话签名密钥，留空回落 `CSH_LICENSE_SECRET` |

以下非敏感值已内建于代码 `ENV_DEFAULTS`，一般无需覆盖：`GITHUB_OWNER/REPO/BRANCH`、`OSS_BUCKET/REGION/ENDPOINT/PUBLIC_BASE/PREFIX`、`DL_MODE`、`DL_DAILY_LIMIT`、`DL_DIRECT_MONTHLY_GB`、`DL_RELAY_MONTHLY_GB`、`GC_ORPHAN_MINUTES`、`GC_STALE_RECORD_HOURS`、`SUBMIT_REQUIRE_SOURCE`、`SUBMIT_MAX_PER_DAY`、`SUBMIT_MAX_PENDING`。

## 6. 状态页

`GET /api/status`（或根路径 `/`）返回：

| 字段 | 含义 |
|---|---|
| `ok` | 整体健康（关键服务全绿） |
| `services` | kv / ossConfig / signConfig / githubConfig / oss / githubApi 六项探测 |
| `features` | 喊话、投稿、直传签名、回声洞、问题反馈、下载闸门六项可用性（含缺失配置提示） |
| `dl` | `{ mode, relayConfigured, relayStatus, backendReady }` 下载通道状态 |
| `ossFiles` | OSS 桶实际对象总数（实时全桶列举） |
| `ossProbeMs` / `ossObjectsProbed` | 列举耗时与对象数 |
| `stats` | 登记文件数、待认领（孤儿登记）数、月度量、最近 GC 结果 |

「已登记文件」与「OSS 文件总数」的差值即账实不符量（登记表外对象），可通过 `/api/registry-sync` 对账。

## 7. 本地开发与冒烟

```bash
node smoke.mjs        # KV/闸门/提交链路冒烟（12 项）
node smoke-blob.mjs   # Blob 专项
node smoke-admin.mjs  # 后台登录 / 签发 / 激活 / 封禁全链路（内存 KV，20 项）
```

已知限制：`@edgeone/pages-blob` 的真实实现只在 EdgeOne 运行时可用，本地 `edgeone makers build` 会因 npm install 覆盖本地 stub 导致 Blob 冒烟假红，以线上验收为准。类型/语法检查：`node --check "functions/api/[[default]].js"`。

## 8. 正版校验（构建签名 / 激活码）

桌面端仓库公开，客户端内的判定可被改掉，因此授权判定完全放在服务端（`licenseGuard`）。

| 请求头 | 来源 | 说明 |
|---|---|---|
| `X-CSH-Build` | 桌面端 | 构建号，形如 `dv1.2.0-insider1.5+20261102T0730Z` |
| `X-CSH-Sig` | 官方包 | `HMAC-SHA256(CSH_BUILD_SECRET, "v1|<buildId>")` 十六进制；密钥不进仓库，打包时注入 |
| `X-CSH-Device` | 桌面端 | 设备指纹，令牌与之绑定 |
| `X-CSH-Lic` | 桌面端 | 授权令牌 `base64url(payload).base64url(HMAC[0..16])` |

放行顺序：令牌有效 → 构建签名有效（并下发 30 天令牌）→ 豁免（浏览器来源 / 旧客户端窗口内）→
`CSH_LIC_ENFORCE` 未开启则只记日志 → 403 `csh_license_required`。

受保护路由：`/api/submit`、`/api/echocave`、`/api/feedback`、`/api/oss-sign`、`/api/announce/*`。
下载（`dl-ticket`/`dl`）、`icon`、`mirror-sign`、`status` 不参与。

浏览器豁免需同时满足：`Origin`/`Referer` 落在 `CSH_LIC_BROWSER_ORIGINS` 内 **且** 请求带
`Sec-Fetch-Mode`（浏览器禁止脚本修改该头，普通 HTTP 客户端通常不带）。属于提高伪造门槛，非安全边界。

激活：`POST /api/license/activate`，body `{ code, device, build, version }`，成功回
`{ success, token, expiresAt }`；失败回 `{ error }`（人话）。激活码 16 字符离线 MAC，
常规由管理后台签发（见 §4.6），应急时可用桌面端仓库 `tools/issue-license-code.mjs` 离线签。
每来源每日尝试上限 `CSH_LIC_TRY_PER_DAY`（默认 30），激活记录写 `lic:d:<device>`，
并同步进后台对账索引 `lic:c:idx` / `lic:dev:idx`。

被封禁的设备在受保护路由与再次激活时均返回 `403 { code: "csh_device_banned", until }`，
不因令牌未过期而放行。封禁记录 `lic:ban:<device>`，`until = 0` 表示永久。

完整判定表、密钥轮换与威胁模型见桌面端仓库 `docs/正版校验与服务端接入.md`；
面向桌面端开发者的接入约束（请求头契约、配额限流、错误码与自检清单）见桌面端仓库 `docs/防滥用接入指南.md`
（`github.com/c1201y/ClassSoftwareHub-windows7`，本地对应 `csh-win7-repo/docs/`）。

## 11. 限流与安全边界

所有按来源的限流都以 `reqIp()` 取到的 IP 为准：优先平台注入的 `eagleeye-real-ip` /
`cf-connecting-ip` / `true-client-ip` / `x-real-ip`，都没有时才取 `X-Forwarded-For` 的
**最后一段**。首段由客户端填写，不可用于限流（否则伪造头即可绕过）。

| 面 | 限制 | 键 |
|---|---|---|
| 后台登录 | 同来源 30 分钟 10 次失败后锁定 | `adm:fail:<ipHash>` |
| 激活尝试 | 同来源每日 30 次（`CSH_LIC_TRY_PER_DAY`） | `lic:try:<ipHash>:<day>` |
| 设备触点登记 | 仅接受 16–64 位十六进制设备码；同来源每日最多登记 500 台**首次出现**的设备 | `lic:reg:<ipHash>:<day>` |
| 教室喊话 | 单配对码最多 128 台在线设备；同来源每日最多新建 100 个配对码注册表 | `gate:ann:d:*` / `ann:pair:<ipHash>:<day>` |
| 回声洞 / 反馈 | 同来源每日各 10 条（两者都会在 GitHub 落提交） | `quota:echo:*` / `quota:fb:*` |
| 投稿 | 同来源每日 6 次、同来源待审 3 条 | 见 §4.1 |

其余边界：`X-Purge-Token` 与后台会话签名均用定长比较；后台 Cookie 为
`HttpOnly; Secure; SameSite=Strict`，写操作额外校验 `Sec-Fetch-Site` 与 `Origin`；
`/admin` 响应带 `Content-Security-Policy: default-src 'none'`（只允许内联样式与脚本）。

**无法在服务端根治的一点**：设备码由客户端自报，篡改客户端即可换一个设备码绕过封禁。
封禁因此是"提高成本"而非硬约束；真要收紧需要把判定绑到构建签名与激活记录的组合上。
